# 移动端验证：5 档宽度与关键交互

> 对应路线图 5.6。目标不是只看页面能否打开，而是验证手机、平板和桌面窄屏下，用户真正会用的抽屉、聊天、地图和记账区域不会被裁切或挡住。

## 1. 验证范围

| 宽度 | 高度 | 代表场景 |
| --- | --- | --- |
| 375px | 812px | 小屏手机 |
| 390px | 844px | 主流手机 |
| 768px | 1024px | 平板竖屏 |
| 1024px | 768px | 平板横屏 / 小笔记本 |
| 1440px | 900px | 桌面基准 |

自动化用例位于 `frontend/tests/mobile.spec.ts`，每档宽度分别覆盖：

- 页面和 body 没有横向滚动。
- 顶部操作区、主标题、主按钮的关键文字不横向裁切。
- “行程资料”和“AI 对话”抽屉完全位于可视区域，关闭按钮可点击。
- 聊天历史展开、发送消息、收到助手回复后抽屉仍可用。
- 账号弹窗完全位于可视区域。
- 生成结果中的地图容器、4 倍速、播放路线、预算摘要和记账卡片可用。

## 2. 本次修复

### 2.1 小屏抽屉被顶部栏抢走点击

在 720px 以下，顶部操作区会换行并变高，抽屉从页面底部向上覆盖。原来的抽屉 z-index 低于吸顶栏，导致关闭按钮可见但点击被顶部栏拦截。

修复方式：

- 720px 以下抽屉提升到 `z-index: 100`，遮罩提升到 `z-index: 95`。
- 721–1100px 使用同样的层级关系，覆盖平板和窄屏笔记本。
- 用户仍使用抽屉内的关闭按钮退出，不依赖被覆盖的顶部栏。

### 2.2 生成结果在 768–1100px 被内容撑宽

结果区使用 CSS Grid 时，默认轨道会受内容最小宽度影响。路线地图、两列资料区和头部操作区叠加后，在 768px 左右会把画布撑到约 1000px，虽然页面通过 `overflow-x: hidden` 隐藏了滚动条，但右侧内容实际被裁掉。

修复方式：

- `.canvas` 和 `.result` 使用 `minmax(0, 1fr)`，允许轨道收缩。
- `.result > *` 设置 `min-width: 0`。
- 双列 `.dossier` 改为 `repeat(2, minmax(0, 1fr))`，避免某一列被长内容锁死。

## 4. 边界说明

移动端专项使用确定性的行程 JSON 和高德地图轻量桩，隔离外部地图服务和真实生成耗时，专门验证布局、滚动和交互状态。真实高德服务的密钥、网络和配额仍需要在生产环境做一次冒烟检查；这不影响本次响应式布局结论。
